# 交互对照清单

按功能分文件维护，参照 `docs/implementation-plan.md`。当前只有应用空壳，
尚未建立或验收具体 Git 工作流条目。

每个条目必须包含以下七个字段：

1. **入口**：入口位置、菜单名称、各平台快捷键及启用条件。
2. **交互行为**：单击、双击、右键、键盘导航、多选和焦点切换。
3. **对话框与反馈**：默认选项、取消行为、成功反馈和失败反馈。
4. **状态恢复**：选择项、滚动位置、过滤条件及布局的恢复方式。
5. **Git 影响与测试**：真实 Git 状态变化及对应测试场景。
6. **源码依据**：对应 intellij-community 源码位置、版本或 revision（如有）。
7. **交付范围**：优先级 P0/P1/P2 与目标版本。

另记录以下三个独立验证状态及证据：

| 状态 | 证据要求 |
| --- | --- |
| 已实现 | 实际功能及生产调用路径已完成；不能只有界面或假成功提示 |
| 已与 IDEA 对照 | 同一测试仓库、同组操作的界面/快捷键/状态恢复对比记录 |
| 已用真实 Git 验证 | 临时真实仓库中的状态和命令结果、失败路径验证记录 |

未验证的状态明确写“未验证”，不以勾选“已实现”代替其余两项。
Windows/Linux 的快捷键和行为差异在相应平台补充对照。
